# User Flows

`PaymentProvider` = ledger simulado (MVP) u Open Payments (opcional).

## Flujo principal (P0, el de la demo)

Login → Onboarding → Tu mes → Meta → Recomendación → Confirmación → PaymentProvider → Resultado → Progreso → Siguiente acción.

Pantallas: 1 Login · 2–7 Onboarding · 8 Dashboard · 9 Detalle de recomendación · 10 Confirmación · 11 Resultado.

## Compra (P1)

"¿Me alcanza?" → Monto → Comprobación contra capacidad segura → Recomendable / No recomendable → Explicación ("te faltarían $30.000 para no tocar lo básico ni tu saldo protegido").

## Mes sin capacidad (P1)

Dashboard → capacidad segura 0 → sin recomendación de ahorro → mensaje sin culpa → revisión cuenta para la racha.

## Meta grupal (P1)

Crear meta → Invitar miembros → Definir porcentajes → Validar 100 % → Activar → Calcular capacidad de cada miembro → Recomendar aporte → Confirmar → Registrar.

## Insights de ciudad (P1)

Analista inicia sesión con rol institucional → elige periodo y cohorte → ve tarjetas agregadas (k ≥ 20) → etiqueta "Datos sintéticos" en la demo.

## Ingreso extraordinario (P2)

Ingreso → Detección → Distribución sugerida → Explicación → Confirmación → PaymentProvider → Actualización.

## Revisión semanal (P2)

Semana → Resumen → Desviación/oportunidad → Acción recomendada → Usuario decide → Resultado.
